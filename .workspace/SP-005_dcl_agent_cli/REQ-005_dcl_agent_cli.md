# REQ-005: DCL Agent CLI

**Версия:** 1.0
**Спринт:** SP-005
**Дата:** 2026-11-24

---

## 1. Цель

Предоставить CLI-инструмент `dcl-agent`, устанавливаемый глобально как
`uv tool` в editable-режиме, для:

1. Компиляции DCL-инструкций в InvocationContext (frames) — основной сценарий
   получения `system_instruction` для authored compiled specs.
2. Инспекции реестра загруженных prompt-модулей и алиасов.

---

## 2. Функциональные требования

### 2.1 Команда `dcl-agent compile`

Компилирует DCL-инструкцию в InvocationContext через существующую
стратегию `GeminiNativeStrategy` (`dcl_agent.strategies.gemini.GeminiNativeStrategy`,
стратегия `DCLAgent` по умолчанию) и выводит результат в stdout.

Порядок Frame-ов определяется этой стратегией: (0) raw DCL-инструкция,
(1) `zero_context_frame`, (2) модуль оператора, (3) операнд, далее —
modifiers (`USING`), goals (`OPTIMIZING_FOR`), sources (`FROM`) в порядке следования.
Другие стратегии (например, `ConcatenationStrategy`) в рамках SP-005 через CLI
не поддерживаются.

#### 2.1.1 Входные параметры

| Параметр | Обязательный | Описание |
|---|---|---|
| `--bundles` | Да | Comma-separated список путей к бандл-директориям |
| `--instruction` | Нет¹ | Строка с DCL-инструкцией |
| `--instruction-file` | Нет¹ | Путь к файлу с DCL-инструкцией |
| `--output` | Нет | Режим вывода: `frames` (default) или `concat` |

¹ Ровно один из `--instruction` / `--instruction-file` обязателен.

#### 2.1.2 Режимы вывода (`--output`)

- **`frames`** (по умолчанию): каждый Frame выводится с заголовком
  `# --- Frame N ---` и пустой строкой-разделителем. Удобен для отладки и
  понимания структуры контекста.
- **`concat`**: все Frame-ы конкатенируются через `\n\n` в единую строку.
  Удобен для прямой вставки в `system_instruction` compiled spec.

#### 2.1.3 Поведение при ошибках

- Если ни `--instruction`, ни `--instruction-file` не переданы — ошибка
  с подсказкой.
- Если бандл-директория не существует — предупреждение (не критичная ошибка,
  Loader уже делает warn). Если реестр пуст — ошибка разрешения алиасов.

### 2.2 Команда `dcl-agent registry`

Выводит состояние реестра: все алиасы (JSON) и список загруженных
модулей (одна строка на модуль).

| Параметр | Обязательный | Описание |
|---|---|---|
| `--bundles` | Да | Comma-separated список путей к бандл-директориям |

### 2.3 Установка как `uv tool`

Пакет должен поддерживать установку командой:

```bash
uv tool install --editable "src/dcl_agent"
```

После установки исполняемый файл `dcl-agent` доступен глобально.
В editable-режиме изменения в `src/dcl_agent/` применяются без
переустановки.

---

## 3. Нефункциональные требования

1. **Совместимость:** Python ≥ 3.12, Windows и Linux.
2. **Без внешних зависимостей CLI:** `cli.py` использует только `argparse`
   из стандартной библиотеки и `dcl_agent.*`.
3. **Stateless:** CLI не хранит состояния между вызовами; каждый вызов
   загружает бандлы заново.
4. **Нет регрессии:** публичный API `DCLAgent` и поведение `MockLLMAdapter`
   не изменяются.

---

## 4. Критерии приемки

1. `dcl-agent --help` выводит справку без ошибок.
2. `dcl-agent registry --bundles <path>` корректно выводит алиасы и модули.
3. `dcl-agent compile --bundles <path> --instruction "EXTRACT Entity('X')"
   --output concat` возвращает конкатенированный InvocationContext,
   идентичный результату notebook-симуляции с `MockLLMAdapter`.
4. Команда `uv tool install --editable src/dcl_agent` успешно устанавливает
   исполняемый файл `dcl-agent`.
5. После изменения файла в `src/dcl_agent/` повторный вызов `dcl-agent`
   отражает изменения без переустановки (editable).
