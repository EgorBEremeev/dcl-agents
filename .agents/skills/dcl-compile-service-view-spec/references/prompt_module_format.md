# Формат prompt module (тип OPERATOR)

Секции YAML в модуле оператора располагаются в следующем порядке (все обязательны):

1. `# METADATA`
   - `id`: уникальный идентификатор (например, `ad-pilot/operations/extract`)
   - `type`: `OPERATOR`
   - `version`: версия формата `Major.Minor` строкой или числом (например, `1.3`)
   - `description`: краткое описание назначения оператора
2. `# IDENTITY`
   - `role`: роль когнитивного агента
   - `worldview`: мировоззрение и базовая установка агента
3. `# COGNITIVE STRATEGY`
   - `instruction`: основная задача оператора
   - `thinking_process`: название процесса мышления
   - `steps: |` — многострочный блок с нумерованными шагами алгоритма
   - `heuristics`: список правил и эвристик (`- "..."`)
4. `# GUARDRAILS`
   - `constraints`: список жестких ограничений и запретов (`- "..."`)
5. `# INTERFACE`
   - `slots`: входные слоты (список объектов с `name`, `type`, `description`)
   - `output_contract`: описание и пример ожидаемого результата
6. `# VERIFICATION`
   - `checklist`: проверочный чеклист для самоконтроля модели перед ответом

## Правила форматирования

- Для `steps` используй конструкцию многострочного литерала:
  ```yaml
  steps: |
    1. "Шаг 1: Описание шага, двоеточия и спецсимволы не ломают парсер."
    2. "Шаг 2: Следующий шаг..."
  ```
  Это гарантирует чистый парсинг YAML без конфликтов ключей и экранирования.
- Идентификатор в реестре `dcl-agent` строится как `<id>/<version>`. Алиас в `index.yaml` бандла обязан указывать на точно такую же версию.
- При корректировке формата или исправлении YAML поднимается **только минорная** версия (например, 1.2 → 1.3). Смысловое содержание модуля в рамках компиляции спеки не изменяется.
